# Besat production environment contract

This contract is for the single-site deployment at `https://besat.org`.
Production values belong in the operator's secret/configuration store, not in
Git. The repository only contains safe examples:

- `backend/docker.env.example` → copy to `backend/docker.env` on the server.
- `frontend/.env.production.example` → copy to `frontend/.env.production`.
- `deploy/production.compose.env.example` → copy to
  `deploy/production.compose.env` for Compose build-time interpolation.

The copied files are gitignored. Never paste their contents into logs or
support tickets.

## Canonical-origin policy

| Host | Policy |
|---|---|
| `https://besat.org` | Canonical application origin. |
| `https://www.besat.org` | Accepted by the gateway only to issue a permanent redirect to `https://besat.org`. |
| `http://besat.org` and `http://www.besat.org` | Permanent redirect to the canonical HTTPS origin. |

The gateway, not Django, owns the redirect and certificate. Django and Next
receive the canonical host and trusted HTTPS forwarding headers from that
gateway.

## Backend variables (`backend/docker.env`)

| Variable | Required | Secret? | Purpose / safe format |
|---|---:|---:|---|
| `DJANGO_SETTINGS_MODULE` | Yes | No | Must be `config.settings.production`; Compose pins this too. |
| `SECRET_KEY` | Yes | **Yes** | Long random value generated by the operator; never an example/default. |
| `DEBUG` | Yes | No | `False`. The production guard rejects `True`. |
| `POSTGRES_DB` | Yes | No | Database name, for example `besat_site`. |
| `POSTGRES_USER` | Yes | No | Dedicated PostgreSQL role. |
| `POSTGRES_PASSWORD` | Yes | **Yes** | Secret matching the PostgreSQL role. |
| `DATABASE_URL` | Yes | **Yes** | PostgreSQL URL using the private Compose service name `db`; never SQLite. |
| `ALLOWED_HOSTS` | Yes | No | `besat.org,www.besat.org`. |
| `CORS_ALLOWED_ORIGINS` | Yes | No | `https://besat.org` only. |
| `CSRF_TRUSTED_ORIGINS` | Yes | No | `https://besat.org` only. |
| `FRONTEND_BASE_URL` | Yes | No | `https://besat.org`; invitation links use this origin. |
| `TRUST_PROXY_HEADERS` | Yes with gateway | No | `True` only when the supplied gateway overwrites forwarded headers. |
| `SECURE_SSL_REDIRECT` | Yes with gateway | No | Keep `False` for the internal HTTP hop; the gateway performs HTTP→HTTPS. |
| `SECURE_HSTS_SECONDS` | Yes with gateway | No | Keep Django HSTS at `0` when nginx owns HSTS; the template adds it at the edge. |
| `ADMIN_URL` | Yes | No | Non-default path chosen by the owner, such as `panel/`; do not advertise it publicly. |
| `SHOP_PAYMENT_PROVIDER` | Before shop traffic | No | Name of a registered real provider. `mock` is forbidden in production. |
| `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD` | If email is enabled | Host/password secret | SMTP delivery configuration; leave host empty only when email is intentionally disabled. |
| `DEFAULT_FROM_EMAIL` | If email is enabled | No | Approved sender address, for example `info@besat.org`. |
| `INTERNAL_HEALTH_TOKEN` | Optional | **Yes** | Long random token for internal deep-health/metrics probes; empty keeps them closed. |
| `ALERT_RECIPIENT_EMAIL` | Optional | No | Operations alert recipient; empty means structured logs only. |
| `WEB_CONCURRENCY`, `GUNICORN_THREADS`, `GUNICORN_TIMEOUT` | Optional | No | Tune after the VPS size is known; keep documented defaults initially. |

`RUN_MIGRATIONS=0`, `COLLECT_STATIC=0`, and `SEED_PUBLIC_DATA=0` are the
production application defaults. Migrations and static collection run once as
the dedicated Compose one-shot services; public-data bootstrap is a separate,
owner-approved operation for a genuinely empty database.

## Frontend variables (`frontend/.env.production`)

| Variable | Required | Secret? | Purpose / value |
|---|---:|---:|---|
| `NEXT_PUBLIC_SITE_URL` | Yes at build | No | `https://besat.org`; webpack-inlined into metadata and image policy. |
| `SITE_URL` | Yes at runtime | No | `https://besat.org`; runtime robots/sitemap origin. |
| `BESAT_BACKEND_API_URL` | Yes at build/runtime | No | `http://backend:8000/api` on the private Compose network. |
| `NEXT_SERVER_API_BASE_URL` | Yes at runtime | No | Same private backend URL for the BFF. |
| `NEXT_PUBLIC_API_BASE_URL` | Yes at build | No | `/api/backend`; browser stays same-origin. |
| `BESAT_TRUST_FORWARDED_FOR` | With gateway | No | `true` only with the supplied header-overwriting gateway. |
| `NODE_ENV` | Yes | No | `production` (set by the image/Compose). |

No frontend variable contains a credential. `NEXT_PUBLIC_*` values are public
and must never be used for secrets.

## Payment contract

The repository currently registers only the development `mock` provider. The
production guard deliberately refuses `SHOP_PAYMENT_PROVIDER=mock`, and the
startup validation rejects an unregistered name. A real provider adapter,
credentials, browser return URL, and server callback/webhook URL must be
provided and tested separately before enabling shop checkout. Browser return
parameters are never sufficient proof of payment.

## Validation without exposing secrets

On the target host, validate names and Compose interpolation without printing
values:

```sh
docker compose --env-file deploy/production.compose.env \
  -f docker-compose.prod.yml config --quiet
docker compose --env-file deploy/production.compose.env \
  -f docker-compose.prod.yml config --images
```

The production settings guard, Docker health checks, and `validate_payment_provider`
command must all pass before traffic is routed.
