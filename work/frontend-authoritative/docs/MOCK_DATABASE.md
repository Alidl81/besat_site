# دیتابیس موقت و مسیر اتصال به بک‌اند

## معماری

مرورگر همیشه به `/api/backend/*` درخواست می‌فرستد. Route Handler فرانت بر
اساس `BESAT_BACKEND_API_URL` یکی از دو مقصد را انتخاب می‌کند:

- `mock://local`: اجرای API موقت روی فایل JSON
- URL واقعی: پراکسی همان درخواست به بک‌اند اصلی

در نتیجه repositoryها، سرویس‌ها، فرم‌ها و صفحات پنل هنگام مهاجرت تغییر
نمی‌کنند. تنها متغیر محیطی مقصد عوض می‌شود.

## فایل‌ها

- داده اولیه قابل بازنشانی: `data/mock-database.seed.json`
- دیتابیس اجرایی محلی: `data/mock-database.local.json`
- قرارداد endpointها: `docs/BACKEND_API_CONTRACT.md`

فایل اجرایی در اولین درخواست از seed ساخته می‌شود و در Git ثبت نمی‌شود.
نوشتن در آن اتمیک و درخواست‌های تغییر‌دهنده به‌صورت ترتیبی انجام می‌شوند.

بازنشانی:

```bash
npm run mock:reset
```

وضعیت دیتابیس:

```text
GET /api/backend/mock/status/
```

## حساب‌ها و داده خصوصی

seed پایدار هیچ حساب آزمایشی، دانش‌آموز، والد، پیام، ثبت‌نام، کلاس یا
رکورد گردش‌کار ندارد. در نتیجه ورود به پنل در حالت mock پیش‌فرض ممکن نیست
و برای پنل باید بک‌اند واقعی و حساب معتبر تنظیم شود.

تست‌های Playwright و smoke با `tests/e2e/prepare-db.mjs` یک دیتابیس مستقل
در پوشه موقت سیستم‌عامل می‌سازند. حساب و رکوردهای آن فقط در همان فایل موقت
قرار می‌گیرند و وارد seed یا دیتابیس local پروژه نمی‌شوند.

## منشأ و حریم خصوصی داده

اطلاعات عمومی مدارس از منابع رسمی زیر استخراج شده است:

- `https://besat-r.com/home.axd`
- `https://besat-r.com/boys-school.axd`
- `https://besat-r.com/girls-school.axd`
- `https://besat-r.com/boys-highschool.axd`
- `https://besat-r.com/girls-highschool.axd`
- `https://besat-r.com/blog-archive.axd`
- `https://www.besat-hs.ir/`

هر رکورد عمومی دارای `source_url` است. تاریخ انتشار خبرهایی که منبع رسمی
تاریخ دقیق قابل اتکا ارائه نکرده، عمداً `null` مانده و تاریخ ساخت seed به
عنوان تاریخ انتشار نمایش داده نمی‌شود.

هیچ نام، شماره تماس، کد ملی یا پرونده خصوصی واقعی یا ساختگی در seed و
دیتابیس local پروژه ذخیره نشده است.

## قابلیت‌های قابل آزمایش

- endpointهای عمومی خانه، درباره ما، تماس، واحدها، اخبار، اطلاعیه‌ها،
  گالری، افتخارات و ثبت‌نام
- ورود، refresh، logout، کاربر جاری، CRUD محتوا، workflow و upload فقط در
  smoke ایزوله تست می‌شوند.
- قابلیت‌های پنل که در بک‌اند واقعی قرارداد ندارند در
  `FRONTEND_BACKEND_ENDPOINT_MAP.md` به‌عنوان gap ثبت شده‌اند و mock منبع
  تعریف قرارداد جدید نیست.

## محدودیت‌های حالت موقت

- فقط برای توسعه و دموی محلی است؛ فایل JSON جایگزین PostgreSQL/MySQL نیست.
- در import دانش‌آموز، CSV پشتیبانی می‌شود؛ پردازش XLSX باید در بک‌اند اصلی
  انجام شود.
- upload موقت حداکثر ۲ مگابایت است و فایل را به data URL تبدیل می‌کند.
- دیتابیس فایل‌محور برای استقرار serverless یا اجرای چند instance مناسب
  نیست.
- permissionهای اصلی باید دوباره در بک‌اند enforce شوند؛ کنترل فرانت به
  تنهایی مرز امنیتی نیست.

## اتصال نهایی

```dotenv
NEXT_PUBLIC_API_BASE_URL=/api/backend
BESAT_BACKEND_API_URL=https://api.example.com/api
```

قرارداد واقعی و gapهای تأییدشده در
`docs/FRONTEND_BACKEND_ENDPOINT_MAP.md` ثبت شده‌اند. PHP برای فرانت Next.js
لازم نیست و بک‌اند فعلی endpoint همگام‌سازی WordPress ندارد.
